ICEbreaker Phase 1
Stakeholder review walkthrough

Review the end-to-end control experience, from setup and ownership through evidence, certification and follow-up.

Open ICEbreaker ·

24 September update — focus for this review

Use the searchable Owner results to select an account. Frequency fields now use predefined choices with a preview and explicit effective period. In Calendar, delete a newly added unused period; records or the currently selected period prevent deletion. In the DTP section, one Confirm procedure current action records the read-only review date and the assigned Owner’s review. The guidance inbox adds filters and a role-specific pending-response badge, and the sidebar scrolls on shorter screens.

Before you begin

Use non-sensitive test material only. Records and actual uploaded files are stored in this browser, not shared across users or devices. The profile switches between labelled test accounts and roles; it is not secure sign-in. All email notices are simulations. No Azure, Microsoft SSO, directory, Teams or ServiceNow integration is connected.

Select Q3 2026 for the initial quarterly-control walkthrough. The original July, Q3 and FY cycles are retained for compatibility; they are not an official Mars calendar. Use one browser to switch between Controller and Owner experiences. Export a backup before changing existing test work.

1. Configure a calendar and deadline

As Controller Admin, open Admin setup → Calendar. Download the calendar template or enter a new period. Supply start/end dates and quarter, half-year and year-end flags. Import, inspect the preview, then apply. Cancel an import once to confirm nothing changes.

Open a control and set its attestation frequency, deadline week and day. Save requirements. Weeks are measured from the period start; an empty week uses period end. An explicit saved due date overrides the rule for that period.

Expected: ordinary periods show periodic attestations; quarter/year-end flags enable corresponding controls. Explicitly activated event-based controls appear in the selected period. Existing started work remains visible.

2. Review global and local requirements

Open a control. Expand the global description. In Controller Admin, confirm that objective, risk and global description are read-only references. Add regional and unit instructions and save. Switch to Control Owner using the bottom-left profile.

Expected: Owners can distinguish the global standard from local instructions. Execution frequency describes the underlying task; attestation frequency describes the Owner’s confirmation, not Controller testing.

3. Assign and acknowledge ownership

Use Admin setup → Ownership to search and select control instances. Search the Owner picker by test name, email or unit and apply an assignment. Test accounts are managed under Test data. Use the profile to select that account and the Control Owner role.

Open My controls, select a control, confirm ownership and understanding, then click Acknowledge & save. Close and reopen it.

Expected: acknowledgement is retained separately. Execution and certification remain incomplete. Other test accounts do not see this control in their own queue.

4. Complete a Controller-approved reassignment

As the assigned Owner, request reassignment to another test account. Confirm that responsibility handover and training have occurred. Submit. Switch to Controller Admin, open the control and approve the request, or retain the current Owner and resolve it.

Expected: assignment does not change until approval. The new Owner must acknowledge ownership and understanding. Existing execution, documents and history remain. Certified executions cannot change Owner in that period.

5. Maintain and retrieve desktop procedures

Open Procedure & execution → Maintain desktop procedure. Enter steps, version and review information. Upload a small test TXT, PDF or Office document. Save a draft or confirm the procedure current. Download the attached file, close the control and reopen it.

Upload a second document/version and save. Download the first version from Version history. Controllers can also maintain DTPs from the control panel.

Expected: actual file content is retained locally and prior versions remain retrievable. Confirming the DTP current also records the assigned Owner’s review, avoiding two equivalent actions. A different Owner can record their own review confirmation.

20 MB per file, 150 MB local workspace. Older filename-only references need re-uploading. Clearing browser data can remove files.

6. Save evidence, draft execution and certify

Set the evidence rule as Controller Admin. As the assigned Owner, add a test evidence file or valid reference link. Select an execution outcome and describe any deviations. Save draft, close and reopen. Review Support & certify and resolve each listed readiness requirement before certifying.

Expected: drafts are visible to Controllers without certification. Required evidence blocks certification when missing. Evidence can be downloaded in the assigned Owner or Controller view. Select a new period to verify confirmations do not carry forward.

7. Reuse guidance across units

In Admin setup → Ownership, select multiple instances and choose a documented source control. Reuse its DTP. Open a target instance and review the copied guidance.

Expected: files are referenced without repeated uploads; prior versions are retained and local confirmation is required. This is a snapshot, not a live synchronized document. Each unit keeps separate evidence, execution and certification.

8. Ask for guidance and receive a reply

Use Ask for guidance within a control. Enter a question and submit. Open Guidance requests to find it. Switch to Controller Admin, open the same inbox and save a reply. Switch back to the requesting test account, read the reply and mark the request resolved. Reopen it if further discussion is needed.

Expected: both parties can see the conversation and its open/answered/resolved status. The request goes to the Controller workflow, not digital support. No email or Teams message is sent.

9. Log and manage a remediation gap

Log a gap from a control with its impact, action and proposed Owner. As Controller Admin, open Gap remediation. Set the remediation Owner, target date and status. Add an optional ServiceNow reference. Supply closure evidence and Controller approval before closing.

Expected: the permanent ICEbreaker ID is unchanged when the external ServiceNow reference changes. The gap appears in reporting. A direct ServiceNow connection and exact additional screenshot fields are not included.

10. Preview reminders and readiness notices

Open Admin setup → Reminders. Inspect the central policies: Periodic 7/2/0, Quarterly 14/7/2/0, Annual 28/14/7/2/0 calendar days before/on the approved deadline. Semi-annual and event-based frequencies stay manual until configured. Generate on a scheduled date twice, then on overdue days 1, 2, 7 and 8.

Expected: one daily Owner digest combines eligible controls. Owner follow-ups occur on days 1, 8, 15 and so on, not daily; Controller escalation occurs on day 7. Certification stops reminders; acknowledgement alone does not. Repeated runs do not duplicate log entries. No email is sent.

Separately preview a Controller readiness notice and guidance follow-ups. Open requests generate a notice on the creation date and every seven days until answered/resolved. Follow the inbox/control links. Readiness notices do not schedule Controller testing or certify a control. Deadline week/day fields are Owner certification deadlines; the period-end versus PEC/YE-close anchor still needs business confirmation.

11. Validate reports and saved views

As Controller Admin, open Reports. Filter by unit, region, Owner, period, status and documentation/evidence criteria. Compare Leadership, Site owners and Controller views. Save and reload a view, clear filters, delete a saved view and download the control and gap extracts.

Expected: on-screen and downloaded results reflect the selected controls. Deleting a saved view does not delete controls. Ownership changes and follow-up workload are visible. Control Owners retain a simple personal dashboard.

12. Validate imports and recovery

Download the controls template from Admin setup → Scope & structure. Import a small test set with one new control and one update. Try an invalid evidence flag or unknown Owner and verify the validation message. Preview and cancel before applying a corrected file.

Under Test data, export a workspace backup including documents. Select that backup, review its contents summary and restore only after protecting the current workspace.

Expected: blank values preserve existing fields and omitted controls are not removed. Execution history is retained. Backup restores local test records and actual document contents in the same browser.

How to record feedback

In the shared backlog, record the item ID, test role/account, control number and unit, certification period, action taken, expected result and actual result. Add a screenshot when helpful. Ready for Review means delivered for your validation, not automatically accepted.

Still outside this release

Production identity/access, shared storage, unattended email, corporate directory/Workday, live ServiceNow/Teams, AI review and predictive features remain deferred. These require enterprise architecture and integration approval. Please also confirm whether a single attestation may cover multiple units; this release deliberately retains per-unit certification.
